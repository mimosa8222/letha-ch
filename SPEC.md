# Letha & Phicia · Character Creator · Development Spec

> This file is for Claude Code. Read it in full before starting any work; whenever you're unsure, come back here.
> Status tags: 【定】confirmed, do not change · 【倾向】basically liked, tweakable · 【未定】still comparing, must be switchable in the system · 【不要】explicitly rejected, do not add

---

## 0. One-line goal

Build a **head-to-toe character creator / dress-up system** that runs in the browser. Two characters: Letha and Phicia.
Every part (hair, eyes, collar, socks, shoes, props…) is swappable, and **every color zone of every part** can have its hue, saturation, brightness and contrast adjusted independently, picked from swatch palettes.
Uses: design exploration, comparing undecided options, and exporting setting sheets for the illustrator.

**Art quality bar: Japanese anime illustration (standing illustrations / galgame portraits), not a cartoon icon, not a chibi doll.**

---

## 1. Read first: lessons from earlier failures

The user has already rejected these attempts. Do not repeat them:

| Problem | What it looked like | Requirement |
|---|---|---|
| Characters drawn in code are too crude | Three.js primitives and hand-written SVG both came out as "cartoon icons" | **Final character art must not be generated by code.** See §2 |
| Collar doesn't read as a collar | It looked like two white discs stuck on the chest, with no thickness and not resting on the shoulders | The collar must follow the shoulder line, wrap from behind the neck, and have edge thickness, a cast shadow and a stitch line |
| Radio "floating away" | It hung on the side of the body with no connection | Props must have anchor points: the strap crosses the chest to the hip and the radio rests against the hip; the earphone cord comes out of the ear, runs along the neck and plugs into the radio |
| Unrest sock oddly long | It reached past the knee | The Unrest sock is a **crew sock**: the top sits at about one third up the calf. Proportions must be anatomically right |
| Squished face | Eyes, nose and mouth crowded into the lower half; on a phone the expression was unreadable | Faces follow anime proportions (see §5.2); preview on a phone screen must be clear; there must be a "zoom to face" button |
| Not wanting to keep playing | Few options, couldn't see the difference between them | There must be a **side-by-side comparison** (A/B split screen) and live slider preview |

## 2. Art route (must be confirmed with the user first)

**Fact: Claude Code writes code; it cannot draw anime-illustration-quality art.** The system can be built in full first; the art assets have to come from a human or a tool. Two options; **confirm with the user which one before starting**:

### Route A: 2D layered illustration (recommended, closest to the "anime illustration" requirement)
- Parts are drawn in layers by an illustrator (or the user themself; they have an XP-Pen-style drawing tablet).
- Claude Code builds the engine: layer compositing, recolor shader, UI, save/load, export.
- **Before art arrives**: generate grey placeholder silhouettes (clear outlines, correct anchor points) so the system can be developed and tested in full. Placeholders must be visibly labelled "placeholder" so they aren't taken for final art.
- The asset spec is in §4. **The full list of parts to commission is in §11; it can be handed directly to the illustrator.**

### Route B: VRoid Studio 3D
- The user models Letha in VRoid Studio (free; built for anime characters, with face shaping, hair and clothing texture painting) and exports `.vrm`.
- Claude Code uses `three` + `@pixiv/three-vrm` to build the dress-up viewer: per-material HSV sliders, clothing mesh toggles, expressions (VRM BlendShape / Expression), poses and scenes.
- Pro: zero drawing needed, 3D can rotate. Con: the look is "VRoid style" rather than an illustration.

> If the user doesn't pick, do the Route A engine with placeholders first; the engine's data structures should not lock out Route B.

## 3. Tech stack (Route A)

- Vite + TypeScript + React (UI) + **PixiJS v8** (canvas compositing and recolor shader)
- State: zustand; persist to IndexedDB (looks saved by the user, palettes)
- Export: PNG (transparent / with background), setting sheet PNG (see §8.4), JSON look file (importable)
- Phone and desktop both supported: desktop = canvas on left / panel on right; phone = canvas on top / panel as a bottom sheet. **Must be tested on a phone-sized viewport**

Directory structure:
```
/assets/{character}/{slot}/{partId}/  line.png  base.png  shade.png  hi.png  zones.png  meta.json
/src/engine   compositing, recolor, anchor points, animation
/src/data     part catalog (generated from meta.json), palettes, preset looks
/src/ui       panels, sliders, compare view, export
/reference    reference images from the user (Phicia's original pixel bust, etc.)
```

## 4. Asset spec (Route A)

### 4.1 Canvas
- One **shared canvas 2000 × 4000 px** for every part; registration points are identical, so layers stack aligned.
- Full-body, front facing or a slight 3/4 view (decide once; every part must match).
- Head about 1/6.5–1/7 of body height (anime proportions, not chibi).

### 4.2 Each part is split into separate layers (this is the basis of recoloring)
| File | Content | Recolorable? |
|---|---|---|
| `line.png` | Line art | Yes, but defaults to "follows the zone color, darkened and hue-shifted" |
| `base.png` | Flat base color, **drawn in grey** (R=G=B) | Yes |
| `shade.png` | Shadow layer (multiply), greyscale | Shadow color is adjustable |
| `hi.png` | Highlight layer (screen/add), greyscale | Highlight color and strength adjustable |
| `zones.png` | Color-zone mask: each pure color (red/green/blue/yellow/magenta/cyan…) marks one zone | Defines how many independently recolorable zones the part has |
| `meta.json` | Slot, layer order, zone names, default colors, anchor points, status tag, mutual exclusions | — |

Example: the saddle shoe `zones.png` has 4 zones: white toe/heel, black saddle, laces, sole.

### 4.3 meta.json example
```json
{
  "id": "shoes_saddle",
  "slot": "shoes",
  "label": "马鞍鞋",
  "status": "定",
  "order": 320,
  "zones": [
    {"key":"upper","label":"鞋头鞋跟","default":"#F3EFE6"},
    {"key":"saddle","label":"马鞍","default":"#1C1919"},
    {"key":"lace","label":"鞋带","default":"#F3EFE6"},
    {"key":"sole","label":"鞋底","default":"#8A3F2C"}
  ],
  "requires": [],
  "hides": [],
  "anchors": {}
}
```

## 5. 捏脸 parameters (adjustable for both characters)

### 5.1 Head and body
- Head size (±8%), neck length, shoulder width (small range)
- Height (only within an "overall scale"; do not distort proportions)
- Skin tone: palette + HSV fine-tuning; blush color and strength; optional dark circles (Letha 【未定】)

### 5.2 Face (default proportions; must look right on a phone)
- Eye line roughly at the vertical middle of the face; eye width ≈ 1/5 of face width; gap between eyes ≈ one eye width
- Mouth about halfway between the bottom of the eyes and the chin; nose is just a dot or a tiny shadow
- Adjustable: eye size, spacing, height, tilt; iris size; pupil shape (round / slit / dot); highlight style (single dot / double dot / none); lash thickness; lower lashes on/off
- **Upper-lid openness slider**: 0 = closed, 0.5 = half-lidded (Letha's default), 1 = wide open
- Eyebrows: thickness, angle (furrowed / worried / flat), position
- Mouth: a set of drawn shapes to switch between (flat / slight smile / open / downturned / biting lip)
- Face deformation: **only** small mesh warps (PixiJS MeshPlane) and the range must be limited, to prevent the "squished face" problem again

### 5.3 Eyes split into layers (required)
White of the eye / iris (gradient: dark top, light bottom) / pupil / highlight / upper lashes / lower lashes / eyelid shadow. Iris color supports **two-stop gradient** adjustment.

### 5.4 Expression presets (combinations of the above)
Sleepy (default), eyes open, slight smile, startled, dazed (eyes glazed, highlights gone, for Phicia-related scenes), eyes closed, on the verge of tears.
Idle animation: blinking (every 3–6 s), breathing (chest rises slightly), hair swaying slightly. Must respect `prefers-reduced-motion`.

## 6. Color system

- Every color zone of every part: **hue / saturation / brightness / contrast** sliders + hex input + eyedropper
- Shade color and highlight color separately adjustable (defaults auto-derived: shade = base hue shifted towards blue/purple and darker; highlight = toward warm yellow and lighter)
- **Palettes**:
  - "1961" palette: faded navy, olive green, mustard, taupe, cream, brick red, pale pink
  - "Eclipse" palette: dark blue, sodium-lamp orange, sickly greenish white
  - "Phicia" palette: grey and white, 1-bit black, mauve pink, dither green
  - Users can save their own palettes
- **Linked colors**: hair ↔ eyebrows ↔ eyelashes (unlinkable); saddle shoe laces ↔ upper
- **Global grading**: overall saturation / brightness / color temperature, and a "film grain" toggle (applies to the export too)
- Implementation: one Pixi filter per part: `grey base × target color` while preserving value variation (screen highlights, multiply shadows); zones separated via `zones.png`

## 8. Features

### 8.1 Wardrobe panel
- Categories: 发型 · 发色 · 脸 · 眼睛 · 眉 · 嘴 · 表情 · 上身 · 领子 · 下身 · 袜子 · 鞋 · 手持 · 配件 · 套装
- Each option shows a thumbnail + status tag (定 / 倾向 / 未定 / 试)
- Filters: "show only confirmed", "show only undecided"

### 8.2 Two modes
- **Final**: only 【定】 + 【倾向】 parts appear; presets "日常服" and "睡衣"
- **Try-on**: everything is available

### 8.3 Comparison
- **A/B split screen**: left and right show two looks; or a slider that splits a single character
- "Switch only this one item" quick compare: hold a key to preview a different color

### 8.4 Export
- PNG with transparent background / with scene, 2× resolution
- **Setting sheet**: one image with full-body front view + face close-up + every color swatch (hex) + item list with status tags, ready to send to an illustrator
- Look JSON (export / import)
- Undo / redo, random (random only within the confirmed range)

### 8.5 Scenes (background layer)
- Small-town street: overexposed daytime / total eclipse (deep blue sky, orange band along the horizon, streetlights switched on)
- Letha's bedroom at night (radio, desk lamp, moon through the window)
- Ouija-board stage (abstract, top-down)
- Plain / grid setting-sheet background
- The scene affects lighting color (a multiplied overall tint), toggleable
